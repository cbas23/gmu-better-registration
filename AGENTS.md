# AGENTS.md

## Project Overview

Browser extension (Chrome/Firefox) that enhances GMU course registration with RateMyProfessors data. Built with **WXT** (Web Extension tooling) + **SolidJS** + **TypeScript**.

## Commands

- `bun install` — install dependencies
- `bun run dev` — start dev server (WXT, auto-reload)
- `bun run dev:firefox` — dev server for Firefox
- `bun run build` — production build (outputs to `.output/chrome-mv3/`)
- `bun run build:firefox` — production build for Firefox
- `bun run compile` — TypeScript type-check only (`tsc --noEmit`)
- `bun run zip` — package extension as .zip

There are **no tests** configured.

## Architecture

- **WXT** manages the extension build, entrypoints, and manifest generation
- `wxt.config.ts` — single config file; uses `@wxt-dev/module-solid`
- `tsconfig.json` extends `.wxt/tsconfig.json` (auto-generated by `wxt prepare`) with SolidJS JSX settings — **do not run `compile` before `bun install`**, since `postinstall` runs `wxt prepare` which generates the `.wxt/` directory and virtual modules
- Entrypoints are auto-detected from `src/entrypoints/` by WXT convention:
  - `background.ts` — service worker
  - `content.ts` — content script (currently targets `*://*.google.com/*`, will need updating for GMU pages)
  - `popup/` — popup UI (SolidJS app, `index.html` + `main.tsx` entry)
- `src/utils/rmp.ts` — RateMyProfessors API client (Zod-validated GraphQL queries, cursor-based pagination, normalized interfaces)

## Key Conventions

- `tsconfig.json` uses `"jsx": "preserve"` + `"jsxImportSource": "solid-js"` — SolidJS-specific JSX transform, not React
- All RMP API responses are validated with Zod schemas before use
- The RMP auth token (`dGVzdDp0ZXN0`) is a public hardcoded token, not a secret
- GMU's RMP school legacy ID is `244` (exported as `GMU_SCHOOL_LEGACY_ID`)
- `rpm-spec.md` is reference documentation for the RMP GraphQL API, not source code

## Testing with Helium (logged-in session)

GMU registration pages require authentication. WXT's dev server is configured in `wxt.config.ts` to launch Helium and preserve the browser profile between runs (`keepProfileChanges: true`).

- **Binary**: `/opt/helium-browser-bin/helium-wrapper` (symlinked as `/sbin/helium-browser`)
- You must **log into GMU once** the first time `bun run dev` opens Helium — the session persists across subsequent runs
- `startUrls` auto-opens `patriotweb.gmu.edu` on launch
- Do **not** add `--user-data-dir` to `chromiumArgs` — web-ext passes its own `--user-data-dir` (to a temp profile) and then connects to CDP via that directory; overriding it breaks the CDP handshake (ECONNRESET)
- To test in regular Chrome instead, remove the `webExt` config from `wxt.config.ts`

## Gotchas

- `.wxt/` is gitignored and auto-generated — never edit it manually; run `wxt prepare` or `bun install` to regenerate
- WXT uses file-based routing for entrypoints — adding a file to `src/entrypoints/` automatically registers it
- `src/entrypoints/popup/` uses SolidJS (`render` from `solid-js/web`), not React
